# Educational content rendering audit

Audit date: 2026-10-17. This is a source audit of the existing application and a record of the bounded renderer increment, not an assertion that every page, imported document, answer or export is correct. Browser acceptance below uses authored fixtures and intercepted HTTP, not real students, authentication or providers.

## Root cause and shared presentation

Teacher lesson section bodies already called `MathText`; they were not an entirely plain-text implementation. The old regular expression recognized `$$…$$`, `\[…\]` and `\(…\)` but not `$…$`, and only applied limited line styling. The new central `components/lumio/math-text.tsx`, `lib/lumio/rich-content.ts` and `lib/lumio/math-display.ts` parse a bounded Markdown subset and math delimiters, reuse KaTeX, escape untrusted HTML, and retain explicit readable fallbacks. Inline presentation is noninteractive phrasing content for headings, buttons and table cells; block presentation supports headings, lists, tables and fenced code.

Original database text is not normalized, decoded or migrated by presentation. Source positions, original quotes and integrity proofs remain tied to the original strings. Rendering mathematics is not mathematical validation, retrieval verification or evidence that a model obeyed instructions.

## Verification evidence and limits

- Central parser/security/print evidence is owned by the shared-renderer suite; read its actual current report rather than inferring success from imports.
- `scripts/test-teaching-content-rendering.cjs` writes isolated results to `docs/next/reports/content-rendering/teacher-consumers.json`; it builds actual teacher/student React components and actual CSS/KaTeX, intercepts authored fixture HTTP, and checks live preview, saving/reload, confirmation before publication, classroom rendering, source-preserving downloads, narrow mobile/light/dark layouts and existing report print. Its explicit synthetic persistence is not production database verification.
- `tests/v7-teaching-ui.browser.js` retains the existing workflow and now confirms the two new lesson preview steps. Historical V7/V9 evidence must not be overwritten by acceptance runs.
- The separately requested durable small-file subsystem uses migration19 dedicated bounded chunks and actual authenticated downloads. Its API/native-adapter/isolated-Turso evidence lives under `docs/next/reports/teaching-files/`; it does not add inline Office/PDF conversion, malware scanning or large-media storage. Do not confuse this with the preexisting text-extraction library or infer completion from a file-input control.

Known limits: bounded Markdown, safe literal malformed-content fallback, presentation truncation limits, no all-device/screen-reader guarantee, no formula correctness guarantee, no full-fidelity Office conversion, no portable rich/math SVG export, no claim of complete V11 scope. Auxiliary source/name labels listed above remain follow-ups unless their separate consumer audit supplies evidence.
