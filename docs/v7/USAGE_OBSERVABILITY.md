# Request outcome observability

The existing admin AI-usage page now has an optional, explicitly loaded breakdown by model/provider, task or canonical user ID, over7/14/31days. It reuses `ai_usage` rather than adding another telemetry store or duplicating billing. Responses contain metadata only, require a fresh administrator with `ai.usage.read` and a matching intended account, and are never cached. The25 displayed groups are bounded; totals include all groups within the chosen window.

Unknown token counts and costs remain `null`, not zero. The sum is labelled **recorded estimated cost**, accompanied by the number of priced/unpriced events. No current provider price or exchange rate is assumed. Only recorded request outcomes are counted: denied retries may be present; fallback provider attempts, consumed tokens on rejected/incomplete generations and lost telemetry may be absent. This report is neither a provider invoice nor complete per-attempt accounting. Credit reservations, deductions and refunds remain in their separate transactional billing ledger.

`node tests/v7-usage-report.cjs` passed14 checks using actual admin authorization/handler and isolated SQLite: ordinary/unauthenticated/stale-admin/account mismatch denial; query/window bounds; empty/null/partial-cost metrics; provider-qualified model grouping; task/user attribution without profile text; time boundaries; telemetry deduplication; bounded groups and totals; explicit evidence limitations; legacy pagination compatibility. Independent review found that the old paginated branch still lacked the intended-account check; the guard now applies before both branches and the pager supplies the canonical header. No live provider, invoice, payment or public deployment was tested. The component also received an independent read-only review of request races, filter reset, keyboard controls and private-data handling; this is not a browser acceptance report.

F02a0 corrected the hybrid-query path that previously used `totalTokens || 0`: absent or invalid upstream usage now stays SQL NULL, while a genuinely observed0 stays0. The32-case RAG billing suite includes five new omitted/zero/positive/string/negative scenarios against actual handlers/SQLite, with unchanged2-credit charge, released holds and same-UUID replay without another provider dispatch. No schema or rate changed; intercepted transport only.

Remaining: per-dispatch provider metadata accounting, approved rate cards and explicit price versions; per-user/feature budgets; reconciliation with provider statements; durable production retention. The [next-phase design](AI_ATTEMPT_ACCOUNTING_PLAN.md) separates unknown provider receipt/cost from authoritative application credit/refund events and does not propose a second billing ledger. It is design only, apart from F02a0. This scoped view does not mark V6 cost engineering complete.
